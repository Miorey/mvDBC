# mvDBC — Murloc Village DBC Files

This repository manages the custom **DBC (DataBase Client)** files for the **Murloc Village** WoW private server (client build **3.3.5a / 12340**).

DBC files are binary data tables read by the game client and server (items, spells, dungeons, …). Here they are stored as **plain CSV files with named columns**: easy to edit, review and diff on GitHub. The binary `.dbc` files are build outputs generated by a small Python tool (stdlib only, no dependencies).

```
mvDBC/
├── tables/                 # SOURCE OF TRUTH — one CSV per DBC table
│   ├── Spell.csv           #   enUS + frFR text in the same file (Name_enUS, Name_frFR, …)
│   ├── Item.csv
│   ├── LFGDungeons.csv

├── dbc.json                # Which tables exist, their locales, and where they are built
├── tools/
│   ├── dbctool.py          # CSV <-> DBC converter (build / check / fmt / import / dump)
│   └── gen_schema.py       # Generate schema/<Table>.json from a WoWDBDefs .dbd file
├── Data/                   # MPQ client patch archives distributed to players
├── modified_DBC_history/   # Changelogs for past events
├── legacy/                 # Old files not yet migrated (see "Known issues")
├── Makefile
└── build/                  # (generated, git-ignored) compiled .dbc files
```

## Quick start

```bash
make check        # validate all CSVs
make build        # compile everything into build/
make server_dbc   # build + assemble server DBCs into prod_serve_dbc/
```

`make build` produces:

| Output | Content |
|--------|---------|
| `build/client/enUS/DBFilesClient/*.dbc` | Client DBCs for the English patch |
| `build/client/frFR/DBFilesClient/*.dbc` | Client DBCs for the French patch |
| `build/server/*.dbc` | Server DBCs (enUS text + server-only tables) |
| `build/optional/DBFilesClient/*.dbc` | Optional client tweaks (lighting) |

## Editing data

1. Edit the CSV in `tables/`: in a text editor, VS Code, or LibreOffice/Excel (save as CSV, UTF-8, comma-separated).
2. Run `make fmt` to normalise the formatting (spreadsheets tend to reformat numbers/hex), then `make check`.
3. Commit. The Git diff shows exactly which row and column changed.
4. Run `make mpq` to rebuild the client patches, and `make server_dbc` for the server (see below).

### CSV conventions

- **Header row = column names** (from `schema/<Table>.json`), e.g. `ID,Category,…,Name_enUS,Name_frFR,Name_flags,…`. Arrays are numbered from 1: `Effect_1`, `Effect_2`, `Effect_3`.
- **One line per record.** Newlines inside text are written as `\n` (and `\r`, `\\`).
- **Localised text**: each text field has one column per locale (`Name_enUS`, `Name_frFR`) plus a `_flags` column. Numeric data is shared, so both locales always stay in sync. The enUS client DBC gets the `_enUS` text and the frFR DBC gets the `_frFR` text.
- **Flags and masks** are written in hex (`0x1A`); everything else in decimal. Hex and decimal are both accepted as input. An empty cell means `0`.
- `-1` means "none" in most integer fields.

### Adding a locale

Add it to `locales` in `dbc.json` (global and per table), then add the matching `*_<locale>` columns, e.g. `Name_deDE`, to the CSV header. `make check` tells you which columns are missing.

### Adding a new table

```bash
curl -LO https://raw.githubusercontent.com/wowdev/WoWDBDefs/master/definitions/AreaTable.dbd
python3 tools/gen_schema.py AreaTable.dbd > schema/AreaTable.json
# add "AreaTable": {"locales": ["enUS", "frFR"], "targets": ["client", "server"]} to dbc.json
python3 tools/dbctool.py import AreaTable enUS=path/enUS/AreaTable.dbc frFR=path/frFR/AreaTable.dbc
make check
```

`import` refuses DBCs whose numeric data differs between locales, or that hold text in a locale slot the CSV doesn't keep, so nothing gets lost silently.

### Inspecting any DBC

```bash
python3 tools/dbctool.py dump Spell some/other/Spell.dbc > /tmp/other.csv
diff <(cut -d, -f1-20 tables/Spell.csv) <(cut -d, -f1-20 /tmp/other.csv)
```

## Building client patches (MPQ)

```bash
make mpq          # build, then pack Data/<locale>/patch-<locale>-<slot>.mpq for every slot in MPQ_SLOTS (K L)
```

`tools/mpqtool.py` packs `build/client/<locale>/` (all of `DBFilesClient\\`) into an MPQ v1 archive and reads every file back to check it.
Each patch carries the **full** current client tables, and the client uses the highest letter, so K and L are rebuilt identical: a player who has either one gets the current data.
Inspect an archive with `python3 tools/mpqtool.py list Data/enUS/patch-enUS-L.mpq` or `extract`.

**The server needs the same data.** Client-side changes the server checks (e.g. `RequiredAreasID`, spell values) only work if the worldserver loads the matching `Spell.dbc`/`Item.dbc` from `make server_dbc` (or the same rows as `*_dbc` SQL overrides). A client-only change can make a spell look usable while the server still refuses it.

## Tracked DBC tables

| Table | Targets | Locales | Description |
|-------|---------|---------|-------------|
| `Spell` | client, server | enUS, frFR | Custom and modified spell data |
| `Item` | client, server | — | Custom item definitions |

From now on, Git history and PR descriptions are the changelog, and the named columns make diffs self-explanatory.

## Known issues

- `legacy/CharStartOutfit.dbc.csv` (old MyDbcEditor format) is not migrated. Row 1 is malformed: a value is missing, so `800001` sits in the 1-byte `OutfitID` column and the item columns are shifted. Once that row is fixed, it can be imported like the other tables (`schema/CharStartOutfit.json` is ready).

## Tools

- **`tools/dbctool.py`**: run `python3 tools/dbctool.py -h`.
- **WoWDBDefs** (https://github.com/wowdev/WoWDBDefs): community column definitions used to generate `schema/`.
- **`tools/mpqtool.py`**: pack, list and extract MPQ archives (`python3 tools/mpqtool.py`).
- **MPQEditor** (Ladik): optional, to inspect MPQ archives in a GUI. Download it separately.
